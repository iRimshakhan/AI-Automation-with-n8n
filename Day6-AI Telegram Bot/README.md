# Day 6 — Two-Way Telegram AI Assistant with n8n

## 📌 Overview

As part of my **AI Automation Journey**, Today I built a two-way conversational AI assistant using **n8n and Telegram**.

The workflow receives a message from Telegram, sends it to an AI Agent for processing, uses Google Gemini as the Chat Model, maintains conversation memory, provides the current date and time when required, and sends the generated response back to the same Telegram conversation.

This workflow was also **published and tested as a live automation** rather than being used only in test mode.

---

## 🚀 What I Built

The final workflow connects:

```text
Telegram User
      |
      v
Telegram Trigger
      |
      v
   AI Agent
   /   |   \
  /    |    \
 v     v     v
Gemini Memory Date & Time
  \     |      /
   \    |     /
    \   |    /
     v  v   v
   AI Response
       |
       v
Telegram - Send Message
       |
       v
Telegram User receives the AI response
```
The result is a conversational AI assistant that can communicate with a user through Telegram.

## 🧩 Components Used

### 1. Telegram Trigger

The workflow starts with the **Telegram Trigger**.

The trigger is configured to listen for incoming Telegram messages. Whenever a message is received, it launches the workflow.

Telegram authentication was configured using an **access token** generated for the Telegram bot. After saving the credential, n8n confirmed that the connection was successful.

---

### 2. AI Agent

The incoming Telegram message is passed to an **AI Agent**.

The agent is responsible for understanding the user's message, processing it using the configured language model, and generating a response.

The AI Agent was connected to a Chat Model, Simple Memory, and Date & Time tool.

---

### 3. Chat Model

A language model was connected to the AI Agent to process natural-language messages.

This allows the Telegram bot to behave like an AI assistant rather than simply returning predefined responses.

---

### 4. Simple Memory

Simple Memory was added so that the AI Agent can remember information from previous messages within the conversation.

bot responded, then i asked:

> "Someone is asking my name, what should i say to them??"

The bot responded successfully by remembering the previous interaction.

---

### 5. Date & Time Tool

A **Date & Time** tool was connected to the AI Agent.

This allows the agent to retrieve the current date when the user asks for date-related information instead of relying on a hardcoded value.

---

### 6. Telegram – Send a Text Message

The second Telegram node is an **action**, rather than a trigger.

Its purpose is to send the AI Agent's generated response back to Telegram.

Two important values needed to be configured:

* **Text** – the AI Agent's output
* **Chat ID** – the ID of the Telegram conversation that initiated the workflow

---

## Working with Expressions

One of the most important concepts I learned on Day 6 was how to use **expressions in n8n to move data between nodes**.

When the Telegram Trigger receives a message, the incoming data is represented as JSON.

The actual user message is located inside the Telegram data structure.

Instead of using the default Chat Input expected by a chat trigger, I configured the AI Agent to use an expression referencing the Telegram message text.

The expression effectively extracts:

```text
$JSON.message.text
```

This allows the message typed by the user in Telegram to become the prompt for the AI Agent.

## Passing the AI Response Back to Telegram

After successfully sending the Telegram message into the AI Agent, the next challenge was returning the AI response to Telegram.

The AI Agent produces an output field containing the generated response.

The Telegram Send Message node was configured to use that output dynamically rather than sending a fixed message.

The expression used is based on:

```text
$JSON.output
```

This means the response generated by the AI Agent becomes the message sent back to Telegram.

## 🆔 Using the Telegram Chat ID

Another important part of the integration was making sure that the response goes back to the **same conversation** that originally sent the message.

The Telegram Trigger provides information about the incoming conversation, including the **Chat ID**.

Instead of manually entering a fixed Chat ID, I used an expression referencing the Chat ID from the Telegram Trigger.

n8n also allows this value to be mapped by dragging and dropping the appropriate field into the Chat ID parameter.

This makes the workflow dynamic and allows it to work with incoming conversations rather than being tied to one hardcoded chat.

## Connecting Memory to the Telegram Chat

The Simple Memory node initially expected a session key associated with a chat-trigger workflow.

Because this workflow uses Telegram, that default configuration needed to be changed.

I configured the memory session key using the **Telegram Chat ID**.

This connects the conversation memory to the specific Telegram chat.

### Why This Matters

Using the Chat ID as the memory key allows the AI Agent to associate previous messages with the correct conversation.

The workflow can also be experimented with by using the Telegram username as the memory identifier, which could allow memory to persist across different chat sessions for the same Telegram user.

## 💡 Key Learning

The biggest learning from Day 6 was understanding how to build a **two-way AI integration**.

Previously, the workflow focused on sending an action outward through an external service.

This workflow introduced a complete conversational loop:

```text
User
 ↓
Telegram
 ↓
n8n
 ↓
AI Agent
 ↓
AI Response
 ↓
Telegram
 ↓
User
```

The integration also introduced an important automation concept:

**Data needs to be correctly mapped between nodes.**

Using expressions and dynamic values such as the Telegram message text, AI Agent output, and Chat ID makes the workflow reusable instead of hardcoding values.
